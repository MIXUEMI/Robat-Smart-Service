设计决策总结

基于讨论确认的技术选型

知识库数据 Mock 数据先行，框架跑通后替换真实文档
工具数量 8 个工具 — RAG检索、天气、定位、设备状态、数据抓取、产品规格、故障排查、工单提交
后端架构 FastAPI + Streamlit — 业务后端和前端 UI 解耦
LLM 模型 DeepSeek (deepseek-chat)
Embedding 本地模型 (sentence-transformers / bge-small-zh)

现在来看 3 种架构方案

点击选择一个方案查看详情

A

LangChain 全栈方案 (推荐)

全面基于 LangChain 生态：create_react_agent + Built-in Tools + Chroma + LCEL。代码量少、社区支持强、和现有技术栈无缝对接

B

混合方案

ReAct 引擎用 LangChain，工具封装、中间件、前端自研。兼顾效率和控制力，但需要平衡边界

C

轻量自研方案

完全自己实现 ReAct Loop、工具注册、向量检索。最大灵活性但工作量大，不利于快速交付
